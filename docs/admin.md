# Admin

Staff routes under `/admin` require a signed-in session. Logins are rows in `admin_users` (SQLite locally, PostgreSQL in production). Customer accounts on `/account` are a separate cookie. See [Customer accounts](account.md).

## Sign in

1. Start `npm run dev` from the repo root.
2. Open http://localhost:3000/admin or the shop sign-in at http://localhost:3000/account.
3. First boot: email `hello@luuxmart.com` and password `j75gUyq2LwbspHL` (or `ADMIN_EMAIL` / `ADMIN_PASSWORD` if those were set when the users table was empty). Signing in on `/account` with that staff email opens `/admin`.

The session is an httpOnly cookie (`luux_admin_session`) signed with `ADMIN_SESSION_SECRET`. Next.js middleware blocks `/admin` except `/admin/login`.

Staff pages share a left panel (`AdminNav`) with Dashboard, Products, Collections, Pages, Settings, Integrations, Marketing, Shipping, Orders, and Messages. The current page is filled black. Sign-in stays a centered form without that panel.

## Pages

| Path | Use |
| --- | --- |
| `/admin` | Counts for products, orders, paid orders, messages |
| `/admin/products` | Each row shows the main photo beside the lamp name. Click the row to open the editor. Add product stays in the header. A search box and a collection menu sit to the left of Add product. All collections shows every lamp. Search matches the lamp name. Product, Price, and Variants sort the list. The first click is A–Z, lowest price, or fewest variants. The second click reverses that. Until a heading is clicked, the newest product stays first. |
| `/admin/products/[id]` | Title, supplier company, link, and contacts, HTML description, options, variants, stock, photos, collections. Each option is a name plus comma-separated values, with Delete on the row. Generate variants builds one row for every combination of the first three options and keeps price, SKU, and stock when that combination already exists. Each variant row has Delete. Link and contacts stay in the admin editor. Delete product is the top-right button and asks for confirmation. Add product (`/admin/products/new`) also has an AI assistant bar. |
| `/admin/collections` | Table of title, handle, product count, and a short description. Edit opens that row’s title, handle, and description. Description switches between HTML source (Current) and the rendered page (Display). |
| `/admin/pages` | Table of title, handle, and a short body. Edit opens that row’s title and HTML body, using the same Current / Display switch. About, Contact, privacy, cookie policy, refund, and terms. |
| `/admin/settings` | Homepage announcement, hero, featured handles, header logo, browser icon, contact, email (Agentic Mail API, SMTP, and IMAP), Facebook, Instagram, Threads, and Pinterest profile links, SEO, cookie notice |
| `/admin/integrations` | AI API base URL, key, and model. Stripe secret key, publishable key, and webhook secret. Facebook, Instagram, and Threads posting tokens. A marketing key for an outside marketer, shown once. That key reads traffic, drafts from shop data, edits drafts, and publishes with the saved social tokens. A blank secret keeps the saved value. Secret boxes stay blank after a save; the gray line under the box shows that a key is stored. These values live in that environment’s database. A deploy does not copy them from this computer to the VPS. The public site JSON does not include these. |
| `/admin/marketing` | Last 30 days of anonymous page views, split into Human, AI, and Web scraping, plus country, where browser visits came from, time on each page, and paid orders. Ask AI drafts a campaign. Confirm and post publishes to the connected channels. Export JSON downloads the same campaign document. See [Marketing](marketing.md). |
| `/admin/shipping` | Flat rates in HKD. Add option, edit the name, amount, and countries, then save. Delete removes that option after confirmation. |
| `/admin/orders` | Paid Stripe orders. Click a row to open a window with that order. The window shows when it was placed and last updated, each lamp’s photo, options, and product description, plus email, contact number, status, invoice address, shipping address, and totals. When the customer used one address, shipping says it is the same as the invoice address. Older orders with no invoice address show the shipping address only. Mark fulfilled or cancel is in that window. Cancelling a paid order returns the stock. Refunds stay in the Stripe Dashboard. |
| `/admin/orders/[id]` | The same order details on their own page: number, email, contact number, status, date, notes, Stripe payment id, line items, subtotal, shipping, total, invoice address, and shipping address. |
| `/admin/messages` | Contact-form notes and inbox mail. `/admin/inquiries` opens this page. |

Shipping (`/admin/shipping`) lists every public row in `shipping_rates`. Add option (`admin.shipping.add`) creates a rate named New option at HK$0.00 for every country (`POST /api/admin/shipping`). Change the name, amount, and countries, then Save rates (`admin.shipping.save`, `PUT /api/admin/shipping/:id`). Countries use `*` for every country, or comma-separated codes such as `HK`. Delete (`admin.shipping.delete`) asks for confirmation and removes that rate (`DELETE /api/admin/shipping/:id`). Checkout and the cart read the same rows. Past orders keep the rate name and amount they were charged. The hidden `paytest` rate stays off this page and cannot be edited or deleted here.

Add product (`/admin/products/new`) shows an AI assistant bar above the form. Paste a public product link and choose Read product (`admin.product.import`). The server reads that page with the AI base URL, key, and model saved on Integrations. A blank model sends `grok-4.7` when the base URL is `api.x.ai`, and `gpt-4o-mini` otherwise. It then fills the title, handle, options, variants, and photos, and puts that link in the supplier Link field. The description is the same spec list used by the other lamps: Material, Colour, Finish, Dimmable, Light Source, Wattage, CCT, Lumin, Plug, Power Source, Shade, Switch, and Size, with `N/A` where the page does not say. Photos are saved under `uploads/products` and shown in the Photos row. Nothing is stored on the product until Save product, which then attaches those photos. Prices stay as the numbers on the source page so they can be corrected to HKD first. A link that is not public http or https is refused.

The product editor stores the supplier as Company (`vendor`), Link (`vendor_url`), and Contacts (`vendor_contact`). Company is included on the shop product JSON. Link and contacts are returned only to staff.

Product description, collection description, and page body share one Current / Display switch. Current is the HTML source. Display renders it with the shop prose styles. Settings text stays plain because those fields are not HTML.

Photos are added by dropping image files on the dashed Photos box. Each thumbnail can be deleted on its own. The photo marked Main is the one shown on product cards, the admin product list, and as the first photo when the shop page opens. Choosing Main on a saved photo calls `POST /api/admin/images/:id/main`, which stores that photo at position 1 and shifts the others. On a new product the choice stays on the form until Save product, which attaches the photos with the main one first. A saved photo is removed with `DELETE /api/admin/images/:id`. A photo that is not saved yet is only taken off the form. Clicking a thumbnail opens Edit photo with AI: preview, reset, the slot name, a short chat, an instruction, increase resolution, and a “Photo for reference only” bar drawn in the browser. An Options side panel lists every option, such as Body Color and Size, with a checkbox for each value (`admin.image.option`). A value ticked on another photo is grey and shows that photo’s slot, so two photos cannot claim it. Apply saves the ticks with the photo, even when the picture itself did not change, through `PUT /api/admin/images/:id`. The ticks are stored in `product_images.option_tags`. When that field is empty, a value is shown as ticked only if every variant with that value already uses the same photo. Apply then sets each variant’s `image_id`: a photo matches a variant when every ticked option agrees with that variant. White alone matches every White size. White plus 35cm matches only that pair. If two photos match, the one with more matching options wins, and a tie uses the earlier option. Apply calls `POST /api/admin/products/images/edit` when the picture changes. That uses the Integrations key and `grok-imagine-image-2.0`, writes the result under `uploads/products`, and returns the new path. A pending photo keeps its ticks on the form until Save product.

The product **Payment test** (`payment-test`) is created on boot and stays unpublished, so it is absent from the shop, search, collections, and the product page. Open it in Products and choose **Pay US$1 test**. That starts a Stripe Checkout for about US$1 in Hong Kong dollars, with no shipping. The card form is the live Stripe page. Only a signed-in staff session can start that charge.

Save product stays disabled while the save and photo attach are running. If the handle is already used, the API returns `A product with this handle already exists.` and the new-product form opens that lamp. Title, variant title, option name, SKU, and photo alt are stored up to 255 characters. A validation failure names the field instead of saying only “Validation error”.

Messages (`/admin/messages`) lists contact-form notes, live chats, and mail from the inbox. All, Contact form, Email, and Chat filter that list. Unread rows are bold. When shows the date on the email, or the time a contact-form note or chat line was sent, newest first. An envelope marks email, a speech mark marks a contact-form note, and a circled mark marks a live chat. Draft reply (`admin.messages.draft`) fills the reply box from the AI key on Integrations. Send reply is still the only action that sends mail. A chat with no email address is answered inside the thread and is not emailed. Open a row to read it, reply, or delete it. Opening Messages lists saved messages right away and checks the inbox in the background. Mail opens as HTML. Attached files can be downloaded, and pictures inside the message load with it. Check mailbox (`admin.messages.sync`) runs that check again. It reads the last 30 days from the inbox, up to 40 messages, and skips mail sent from this shop’s own addresses. A later reply that references an earlier message is attached to that thread and marks it unread. Send reply uses the Agentic Mail API when a token is saved, and SMTP otherwise. Delete removes the thread and, for a contact-form note, the original inquiry. Older contact-form rows are copied into this list on the next view.

A visitor’s note on `/pages/contact` is stored immediately. When outgoing mail is saved, a copy is sent to the contact Email address. A reply to that copy is attached to the same message.

Email settings are the Email section on Settings. The Agentic Mail API token comes from Hostinger → Emails → the domain → Agentic mail → API access. Paste it once; a blank field keeps the saved token. Check API (`admin.settings.mail_api_check`) calls the mail API and shows the mailbox that token can reach. When the token is saved, Check mailbox and Send reply use `https://api.mail.hostinger.com` for that mailbox. No SMTP or IMAP setup is required. From address, when it matches one of the token’s mailboxes, chooses which mailbox. SMTP and IMAP are used only when the token is blank. Outgoing mail is the SMTP host, port, SSL, username, password, from name, and from address. Incoming mail is the IMAP host, port, SSL, username, and password. A blank password keeps the saved one. The token, webhook secret, and passwords stay in that environment’s database and are left out of the public site JSON. A Hostinger webhook for new mail can POST to `/api/mail/webhook` with the saved secret as a bearer token. Messages refreshes while that page is open. A round sage chat icon opens the shop chat. It answers shipping, contact, one clear product, and policy questions from the database. Any other question is passed to the same AI key. If that cannot answer, or the visitor chooses Ask a person, the thread is left unread for staff. Port 587 usually leaves SSL off. Port 465 and IMAP port 993 use SSL.

Public buttons use `helpKey`. Tip text lives in `help_tips` and is upserted on API start.
